# Yeast transcriptional noise pipeline

Reproducible R pipeline for genome-wide noise evolution in S. cerevisiae (YPS1000), S. eubayanus, and their F1 hybrid (10x scRNA-seq, allele-specific). Scientific context and settled decisions live in @docs/project_context.md. Read it before changing any analysis logic.

## Files
- `analysis/analysis.R` main analysis, organized in numbered sections (1, 2.1, 2.3, 4, 6.1 ... 8).
- `R/setup.R` session setup shared by `analysis.R`, `power_analysis.R` and `external_validation.R`: renv check, project paths and output folders, class names, color palettes, and `R/functions.R`. Each script starts with `library(here); source(here("R", "setup.R"))`. Defines no functions.
- `R/functions.R` helper functions sourced by the main script.
- `analysis/power_analysis.R` Section 10 (power analysis) with its functions in `R/functions_power.R`, also sourced by `power_grid.R`. Sections 10.1 to 10.8 simulate the total contrast; 10.9 to 10.14 simulate cis and trans on paired-allele data (`power_modes_grid.R`, `power_modes.sub`). Reads `PR`, `N.PERM`, `N.SIM` and the real design (hybrid and parent cell counts, `SPLIT.FRAC`) from the Section 2 checkpoint. The simulations test the dispersion axis as the pipeline does (shifted bootstrap null, resolution gate; untested datasets count as not called) and the mean axis by permutation.
- `analysis/external_validation.R` Section 9 (comparison with published data) with its functions in `R/functions_external.R`. Reads `GENES` and `CONTRAST.FITS` from the Section 2 checkpoint.
- `analysis/checks/` validation checks of the methods document (`docs/methods.md`), separate from the main analysis: `checks_sim.R` (simulation checks A1, A2, A4, A7, B2 to B4, C4, C7, D5, D6, E1, E3, F1 to F4, and the inputs and merge of the null calibration array `null_calibration_grid.R`, `null_calibration.sub` for D1 to D4, D7, D10), `checks_data.R` (data checks from the Section 1 and 2 checkpoints and a local bootstrap of a gene subsample) `checks_text.R` (G2 DOIs through Crossref, G3 equations, `REPORT.md`) `estimator_leak.R` (Cox-Reid against the Appendix A moment estimator by mean count and phi, and the leak test of mean differences into dispersion contrasts; needs only the Section 1 checkpoint) and `artefact_tests.R` (tests T0 to T12 of why the data depart from the NB, with functions in `R/functions_artefacts.R` and the simulation array `artefact_null_grid.R`, `artefact_null.sub`; needs only the Section 1 checkpoint) and `estimator_mse.R` (M1: bias, variance and MSE with their SEs of the Cox-Reid and Appendix A dispersion estimators over the data's mu and phi ranges on the observed depths, for gamma, lognormal and bimodal expression factors; needs only the Section 1 checkpoint) and `state_conditioned.R` (SC1 to SC3: each gene's Cox-Reid dispersion with and without continuous cell-state scores from GO modules in the mean, the gene left out of its own module, and the cis and trans contrasts and own slopes under both; needs only the Section 1 checkpoint). Their functions, including the shared generator `sim_hybrid_dataset()`, are in `R/functions_checks.R`. Results go to `results/checks/` (one `<ID>.rds` each and `summary.csv`); `docs/validation_checks.md` records the code and document mismatches and the latest numbers.
- Cluster scripts, each a standalone R script plus a `.sub` SLURM file

## Environment
- Local: RStudio on Windows. Cluster: Negishi (RCAC), account `bphm`, partition `cpu`, module `r/4.5.2`.
- Both environments are in R 4.5.x with Seurat v5. Use one shared dated Posit Package Manager CRAN snapshot for both.
- Section 2 of `analysis/analysis.R` computes offsets as direct library-size factors (no scran): a parent's offset is its library over the median parental library, each hybrid allele is offset by half the cell's hybrid depth, and the summed hybrid by the full depth. The Sc share is not an offset. Section 1.2 estimates it with `share_terms()` (`C.HAT`, `C.BAR`, `VAR.C`, `R.C`, `R.E`, `SHARE`, `SHARE.TABLE`) and sets `OFFSET.CBAR` = log2[c-bar / (1 - c-bar)], the log2 ratio of the two abundance factors: every allele mean is divided by its abundance factor, 2 c-bar or 2 (1 - c-bar), before any contrast (`.correct_means()`), so the cis contrast needs no separate offset and the per-genome hybrid mean is the average of the corrected alleles. Dispersion fits carry the transcriptome share corrections: `share_r` (`SHARE.R`, `share_r_groups()`, eta_Hc and eta_He) for the hybrid alleles and `share_sub` for the summed counts (`ploidy_components()`, Methods Appendix B), applied before truncation at zero; Section 1.2 sizes the share term against `SHARE.TOL` times the median allele dispersion (`SHARE.DISP`), and Section 2.2 tabulates the per-subset offsets (`SPLIT.OFFSET`). 
- Claude Code cannot reach the cluster. Write the scripts and `.sub` files, never run `sbatch` or assume cluster output exists.

## Architecture rules
- Cluster pattern: the main analysis packages inputs locally, saves an `.rda`, the cluster script computes, and the main analysis loads the output and verifies that keys match. Keep new cluster work in this pattern.
- NuPoP runs only on the Linux cluster. Its compiled Fortran aborts the hosting R process on Windows regardless of input.
- Bootstrap resampling draws all indices before any Seurat call (`make_boot_ky()`). `RunPCA()` reseeds the global RNG, so a single `set.seed()` before a loop collapses the draws. `collapse_score()` should stay near 0 (0.01 confirmed).
- Fix architectures, not individual crash triggers.
- Checkpoints follow `sectionN_checkpoint.rda`. If a refactor adds an object that downstream sections need, add it to the checkpoint

## Conventions
- R files use Windows CRLF line endings. `.sub` SLURM files use Unix LF line endings. `.gitattributes` enforces both. Keep it intact.
- Each section of an analysis script starts with `set.seed(SEED.SECTION + n)` (`SEED.SECTION` is defined in `R/setup.R`). A step that needs its own reproducible stream draws it through `with_local_seed(seed, expr)`, which restores the caller's random state.
- Check scalar conditions. Use `&&` and `||` only with length-one logical values. A parse-based scan of every `&&` and `||` in `R/`, `analysis/` and `cluster/scripts/` found only scalar operands.
- Write a function only when its code runs more than once: it is called from two or more places, or it is applied across many items (`lapply`, `sapply`, `vapply`, `Map`, `mapply`, `apply`, `parLapply`, `mclapply`). Code that runs once is written inline where it runs, so a reader follows the steps in order.
  - `analysis/analysis.R`, `analysis/power_analysis.R`, `analysis/external_validation.R`, `R/setup.R` and the cluster scripts define no named functions. A function that is applied across items, or called from two or more places, lives in `R/functions.R`, and is passed to the apply call with its other inputs as named arguments (`lapply(X, name, arg = value)`). A short one-line anonymous function in an apply call (`sapply(x, function(g) cor(a[g], b[g]))`) is fine inline and should not become a separate function. A multi-line body belongs in a named function in `R/functions.R`. Use `[[` for plain accessors.
  - A once-used step in `analysis.R` or a cluster script is written inline (a `local({ ... })` block when it needs private variables), with its concept comment above it.
  - A function that PSOCK workers need by name must be a top-level function in `R/functions.R` (`neg_binom_fit_offset`, `.fit_one`); `fit_counts_offset()` finds such dependencies from the code.
  - Before adding a function, check that it will run more than once; inline it if not.
- Noise axis: `DISP` is the dispersion phi (Var = mu + phi mu^2); theta = 1 / phi is the NB size and behaves as burst frequency, and `.fit_one()` returns both. The mean is the ratio estimate sum(y) / sum(offset), free of phi, and phi maximizes the Cox-Reid adjusted profile likelihood over log(phi) (`.cr_loglik()`; phi from about 3e-7 to 55, fits at either end are recorded as `HIT_RANGE`), with phi = 0 when the adjusted slope at zero is not positive. There is no `PHI.FLOOR`; truncation at zero comes after the share corrections. A group's dispersion is resolved when at most `RESOLVED.ZERO.MAX` (2.5%) of its bootstrap replicates refit to zero (Methods: Informative estimates); `boot_contrasts_one()` returns each group's zero fraction (`zero_<dataset>`). Every fit also carries its one-sided 95% likelihood bounds at `BOUND.CRIT` = 2.71 (`dispersion_bound_stats()`: `DISP_LOWER`, `DISP_UPPER`, and the boundary `LRT`). `GENE.TABLE` holds the fits, bounds, zero fractions and `<dataset>.resolved` for every gene and dataset, one definition flag per scale and mode (`mean_<mode>_valid` informative means; `raw_<mode>_valid` phi >= 0 and `log_<mode>_valid` phi > 0 in the noise source; `bsize_<mode>_valid`, `rbsize_<mode>_valid` and `kbal_<mode>_valid` in their own sources), the test flags `resolved_<noise|bsize|kbal>_<mode>` and `in_matched_set` (resolved in every dataset of every partition, informative means). The definition flags say which estimates exist (`GATES`, `apply_gate()`: a contrast the fits do not define is NA); a defined contrast whose groups are not all resolved keeps its estimate and bootstrap interval and gets no p-value (`.QUANTITY.RESOLVE`, masked in `PR` before BH). For total and cis with one resolved group, `BOUNDS.CALLS` and `BOUNDS.SEPARATION` record whether the resolved group's lower bound exceeds the other's upper bound. `GENES` is the matched set that every main-text comparison and downstream log2 analysis uses, set after the bootstrap; the supplementary tables use each per-contrast set (`GENE.SET.SIZES`, `EXCLUDED.COUNTS` give the sizes, the exclusions by reason and the tested and unresolved counts; `RESOLUTION.SENSITIVITY` the matched set at other thresholds). The jobs run on the inference set `GENES.INFER` (every gene with at least one defined contrast). The hybrid cells are split four times by depth, at `SPLIT.FRAC$f_mean` (mean), `f_disp` (noise), `f_kbal` (kinetic balance) and `f_bsize` (burst size), the last two pooled over genes resolved in the pilot (`PILOT.RESOLVED`) and fitting mean and dispersion on the same cells, giving 21 datasets (`.DRAW.KEY`); the summed counts `HYB.COMB` are fitted for reporting only (phi_Sigma, Appendix B) and enter no contrast (`.CONTRAST.GROUPS`). Every noise contrast is reported on two scales from the same refits: a log2 contrast of phi (the `disp_*` columns of `BURST.CONTRASTS` and `PR`) and a raw difference of phi (the `rdisp_*` columns). `fit_dispersion(method = "NB" or "weighted")` is the shared fitting interface (`.fit_one()` is its NB wrapper), and every dispersion contrast (total, cis, trans, mid, par) is reported for all four combinations of scale and estimator: log2 x NB (`disp_*`, the primary), raw x NB (`rdisp_*`), log2 x weighted method of moments (`wdisp_*`) and raw x weighted (`wrdisp_*`), each with a bootstrap estimate, SE and interval and a null p-value and BH q-value in `PR`. Every contrast is a weighted sum over its groups (`.MODE.WEIGHTS`, lambda of +-1 or +-1/2). Means are log2 x NB only. The contrasts `dom` and `dpar` are named `mid` and `par` (dominance stays the umbrella term in text and labels). Route A: the mid and par contrasts compare the per-genome hybrid, built from the two corrected allele fits of all hybrid cells (mean (mu_Hc + mu_He) / 2; dispersion their geometric mean on the log2 scale and arithmetic mean on the raw scale; CV2_H = 1 / mu_H + (phi_Hc + phi_He) / 2), with the parents. The ploidy shifts delta and delta_raw and the other Appendix B quantities are reported only (`APPENDIX.B`, `ROUTE.CHECK`). Burst size is b = mu phi, so `bsize` = mean + disp with both from the burst size partition for cis and trans (`.BSIZE_SOURCE`); kinetic balance is kappa = theta / b, so `kbal` = -mean - 2 disp with both from the kinetic balance partition (`.KBAL_SOURCE`). Raw versions (`rbsize_*`, `rkbal_*`, `wrbsize_*`, `wrkbal_*`) are the difference of b = mu phi (defined at phi = 0) and of kappa = 1 / (mu phi^2) (class 1 only) between groups on the per-genome scale of the rates (`.contrast_burst_raw()`). Bootstraps give intervals, standard errors and the resolution of each group: a refit at phi = 0 is -Inf on the log2 scale and stays in the draws, the log2 interval is the 2.5% and 97.5% percentiles and the SE the interquantile range / 3.92 (`.boot_summary()`), and the fraction of replicates at zero is `_zero` per contrast and `zero_<dataset>` per group. Each draw resamples the parents and the undivided hybrid cells once, each copy keeping its memberships in the four partitions (`make_draws()`), and refits the share terms on its resampled hybrid cells. Every p-value comes from the null generator (`gene_perm`, `null_contrasts_one()`), where every draw is refitted with the observed estimators and share corrections: permutations for the log2 mean contrasts (total: pooled parents; cis: swapped rescaled allele counts; trans: each parent pooled with the same-genome allele of the trans cells, whose offset carries the abundance factor and the level factor k; par: summed rescaled allele counts pooled with one parent), a simulation from the fitted model (`N.SIM` draws) for the mid mean (null allele means scaled to the midparent, alleles simulated with the dispersion their uncorrected fit would show and a shared extrinsic factor of variance sigma_d, `sim_alleles()`), and shifted bootstrap nulls (`N.SIM` draws of `NULL.DRAWS`, seed `SEED.NULL`) for every dispersion, burst size and kinetic balance contrast: each draw resamples the cells as the bootstrap does, refits every group with its share terms refit, and multiplies each refitted dispersion by the ratio of its null value to its fitted value (null values by projection on each scale, `null_phi_log2()`, `null_phi_raw()`, `null_phi_kinetic()`; total and cis raw tests reuse the log2 draws). An infinite log2 null draw counts as extreme in `perm_pval()` and its rate is recorded (`_infrac`). cv2 and the raw burst quantities have no null in the Methods and carry no p-value. Every classification is per comparison: `classify_reg()` needs the cis and trans p-values, `classify_dom()` both parent contrasts, and a gene without them is classified NA (distinct from Ambiguous), so the classified genes differ by quantity (`CLASSIFIED.COUNTS`). `CONTRAST.FITS`, `CONTRAST.MATS` and `PLOIDY.SHIFT` stay on `GENES`, which the sections that need every dataset use. `GENE.TABLE` also keeps the fit status (NB and weighted) and `ANALYSIS.STATUS` records for every gene, quantity and mode whether it was eligible, run, estimated, given a bootstrap interval, tested and significant (`ANALYSIS.COUNTS` tallies them).
- Select Seurat columns by name, never by position (Seurat v5 changes `FindMarkers` output order).
- Validate numeric inputs at function entry (for example `BSIZE` in `SPLIT.FITS`).
- Do not commit data, `.rda` checkpoints, or cluster output. Keep them in `.gitignore`.

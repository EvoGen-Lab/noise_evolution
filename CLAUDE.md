# Yeast transcriptional noise pipeline

Reproducible R pipeline for genome-wide noise evolution in S. cerevisiae (YPS1000), S. eubayanus, and their F1 hybrid (10x scRNA-seq, allele-specific). Scientific context and settled decisions live in @docs/project_context.md. Read it before changing any analysis logic.

## Files
- `analysis/analysis.R` main analysis, organized in numbered sections (1, 2.1, 2.3, 4, 6.1 ... 8).
- `R/setup.R` session setup shared by `analysis.R`, `power_analysis.R` and `external_validation.R`: renv check, project paths and output folders, class names, color palettes, and `R/functions.R`. Each script starts with `library(here); source(here("R", "setup.R"))`. Defines no functions.
- `R/functions.R` helper functions sourced by the main script.
- `analysis/power_analysis.R` Section 10 (power analysis) with its functions in `R/functions_power.R`, also sourced by `power_grid.R`. Sections 10.1 to 10.8 simulate the total contrast; 10.9 to 10.14 simulate cis and trans on paired-allele data (`power_modes_grid.R`, `power_modes.sub`). Reads `PR`, `N.PERM` and the real design (hybrid and parent cell counts, `SPLIT.FRAC`) from the Section 2 checkpoint.
- `analysis/external_validation.R` Section 9 (comparison with published data) with its functions in `R/functions_external.R`. Reads `GENES` and `CONTRAST.FITS` from the Section 2 checkpoint.
- Cluster scripts, each a standalone R script plus a `.sub` SLURM file

## Environment
- Local: RStudio on Windows. Cluster: Negishi (RCAC), account `bphm`, partition `cpu`, module `r/4.5.2`.
- Both environments are in R 4.5.x with Seurat v5. Use one shared dated Posit Package Manager CRAN snapshot for both.
- Section 2 of `analysis/analysis.R` computes offsets as direct library-size factors (no scran): a parent's offset is its library over the median parental library, each hybrid allele is offset by half the cell's hybrid depth, and the summed hybrid by the full depth. The Sc share is not an offset. Section 1.2 estimates it with `share_terms()` (`C.HAT`, `C.BAR`, `VAR.C`, `R.C`, `R.E`, `SHARE`, `SHARE.TABLE`) and sets `OFFSET.CBAR` = log2[c-bar / (1 - c-bar)], which `.contrast_value()` subtracts from the cis mean contrast (trans inherits it); mid and par mean contrasts rescale each allele by its abundance factor 2 c-bar or 2 (1 - c-bar) before averaging, and the permutation nulls pair each hybrid allele's counts with its offset times the abundance factor. Dispersion fits carry the transcriptome share corrections: `share_r` (`SHARE.R`, `share_r_groups()`) for the hybrid alleles and `share_sub` for the summed hybrid (`ploidy_components()`, Methods Appendices C and D), applied before truncation at zero; Section 1.2 sizes the share term against `SHARE.TOL` times the median allele dispersion (`SHARE.DISP`), and Section 2.2 tabulates the per-subset offsets (`SPLIT.OFFSET`). `analysis/sim_inputs.R` and the estimator simulations still model the earlier scran haplotype offsets with `scran::computeSumFactors` (they need scran installed) and have not been updated to the library-size offsets.
- Claude Code cannot reach the cluster. Write the scripts and `.sub` files, never run `sbatch` or assume cluster output exists.

## Architecture rules
- Cluster pattern: the main analysis packages inputs locally, saves an `.rda`, the cluster script computes, and the main analysis loads the output and verifies that keys match. Keep new cluster work in this pattern.
- NuPoP runs only on the Linux cluster. Its compiled Fortran aborts the hosting R process on Windows regardless of input.
- Bootstrap resampling draws all indices before any Seurat call (`make_boot_ky()`). `RunPCA()` reseeds the global RNG, so a single `set.seed()` before a loop collapses the draws. `collapse_score()` should stay near 0 (0.01 confirmed).
- Fix architectures, not individual crash triggers.
- Checkpoints follow `sectionN_checkpoint.rda`. If a refactor adds an object that downstream sections need, add it to the checkpoint

## Conventions
- R files use Windows CRLF line endings. `.sub` SLURM files use Unix LF line endings. `.gitattributes` enforces both. Keep it intact.
- Each section of an analysis script starts with `set.seed(SEED.SECTION + n)` (`SEED.SECTION` is defined in `R/setup.R`). A step that needs its own reproducible stream draws it through `with_local_seed(seed, expr)`, which restores the caller's random state.
- Check scalar conditions. Use `&&` and `||` only with length-one logical values. A parse-based scan of every `&&` and `||` in `R/`, `analysis/` and `cluster/scripts/` found only scalar operands.
- Write a function only when its code runs more than once: it is called from two or more places, or it is applied across many items (`lapply`, `sapply`, `vapply`, `Map`, `mapply`, `apply`, `parLapply`, `mclapply`). Code that runs once is written inline where it runs, so a reader follows the steps in order.
  - `analysis/analysis.R`, `analysis/power_analysis.R`, `analysis/external_validation.R`, `R/setup.R` and the cluster scripts define no named functions. A function that is applied across items, or called from two or more places, lives in `R/functions.R`, and is passed to the apply call with its other inputs as named arguments (`lapply(X, name, arg = value)`). A short one-line anonymous function in an apply call (`sapply(x, function(g) cor(a[g], b[g]))`) is fine inline and should not become a separate function. A multi-line body belongs in a named function in `R/functions.R`. Use `[[` for plain accessors.
  - A once-used step in `analysis.R` or a cluster script is written inline (a `local({ ... })` block when it needs private variables), with its concept comment above it.
  - A function that PSOCK workers need by name must be a top-level function in `R/functions.R` (`neg_binom_fit_offset`, `.fit_one`); `fit_counts_offset()` finds such dependencies from the code.
  - Before adding a function, check that it will run more than once; inline it if not.
- Noise axis: `DISP` is the dispersion phi (Var = mu + phi mu^2); theta = 1 / phi is the NB size and behaves as burst frequency, and `.fit_one()` returns both. The mean is the ratio estimate sum(y) / sum(offset), free of phi, and phi maximizes the Cox-Reid adjusted profile likelihood over log(phi) (`.cr_loglik()`; phi from about 3e-7 to 55, fits at either end are recorded as `HIT_RANGE`), with phi = 0 when the adjusted slope at zero is not positive. There is no `PHI.FLOOR`; truncation at zero comes after the share corrections. Every dispersion estimate has a class (`dispersion_class_stats()`, thresholds `CLASS.ALPHA`, `CLASS.EPS`): 1 resolved above zero (boundary LRT against Poisson rejects), 2 resolved near zero (upper 95% bound on phi times the mean count below `CLASS.EPS`), 3 uninformative, assigned after the share correction from the observed fits and carried into the bootstrap and permutation jobs. `GENE.TABLE` holds the class and its statistics for every gene and dataset and one flag per scale and mode: `mean_<mode>_valid` (informative means), `raw_<mode>_valid` (classes 1 or 2), `log_<mode>_valid` (class 1) and `kbal_<mode>_valid` (class 1 in the kinetic balance source), plus `poisson_like_<mode>` and `in_matched_set` (class 1 in every dataset of every partition). `GENES` is the matched set that every main-text comparison and downstream log2 analysis uses; the supplementary tables use each per-contrast set (`GENE.SET.SIZES`, `EXCLUDED.COUNTS` give the sizes and the exclusions by reason). The jobs run on the inference set `GENES.INFER` (every gene with at least one eligible comparison) and set a contrast a gene does not qualify for to NA (`GATES`, `apply_gate()`). The hybrid cells are split three times by depth, at `SPLIT.FRAC$f_mean` (mean), `f_disp` (noise) and `f_kbal` (kinetic balance, pooled over class 1 genes in the pilot; mean and dispersion fitted on the same cells), giving 17 datasets (`.DRAW.KEY`). Every noise contrast is reported on two scales from the same refits: a log2 contrast of phi (the `disp_*` columns of `BURST.CONTRASTS` and `PR`) and a raw difference of phi (the `rdisp_*` columns). `fit_dispersion(method = "NB" or "weighted")` is the shared fitting interface (`.fit_one()` is its NB wrapper), and every dispersion contrast (total, cis, trans, mid, par) is reported for all four combinations of scale and estimator: log2 x NB (`disp_*`, the primary), raw x NB (`rdisp_*`), log2 x weighted method of moments (`wdisp_*`) and raw x weighted (`wrdisp_*`), each with a bootstrap estimate, SE and interval and a permutation p-value and BH q-value in `PR` (the par ones also `_p_ploidy` and `_p_ind`; the mid null is corrected by the shift of each synthetic hybrid). Means are log2 x NB only. The contrasts `dom` and `dpar` are named `mid` and `par` (dominance stays the umbrella term in text and labels). The mid and par noise contrasts add the ploidy shift (log2 delta, raw delta_raw; `ploidy_components()`), refit in every bootstrap replicate with the share terms; the permutation nulls keep the observed shift. Burst size is b = mu phi, so `bsize` = mean (mean split) + disp (noise split); kinetic balance is kappa = theta / b, so the main `kbal` = -mean - 2 disp with both from the kinetic balance split for cis and trans (`.KBAL_SOURCE`), and `kbalsup` is the supplementary -mean (mean split) - 2 disp (noise split); the two need not agree. Raw versions (`rbsize_*`, `rkbal_*`, `wrbsize_*`, `wrkbal_*`) are the difference of b = mu phi (defined at phi = 0) and of kappa = 1 / (mu phi^2) (class 1 only) between groups on the per-genome scale of the rates (`.contrast_burst_raw()`). Bootstraps give intervals and standard errors only: a refit at phi = 0 is -Inf on the log2 scale and stays in the draws, the log2 interval is the 2.5% and 97.5% percentiles and the SE the interquantile range / 3.92 (`.boot_summary()`), the fraction of replicates at zero is `_zero` and genes above `BOOT.ZERO.FLAG` are flagged (`_zeroflag`, `BOOT.ZERO.SUMMARY`), never reclassified. Every p-value comes from the permutation job (`gene_perm`), where an infinite log2 null draw counts as extreme in `perm_pval()` and its rate is recorded (`_infrac`). Its trans test of each noise quantity is a resampling null (`permute_contrasts_one(resamples = NULL.DRAWS)`: the resample distribution of the trans contrast recentered on its observed value); the pooled-relabeling p-values are kept as `*_trans_p_pooled`. Every classification is per comparison: `classify_reg()` needs the cis and trans p-values, `classify_dom()` both parent contrasts, and a gene without them is classified NA (distinct from Ambiguous), so the classified genes differ by quantity (`CLASSIFIED.COUNTS`). `CONTRAST.FITS`, `CONTRAST.MATS` and `PLOIDY.SHIFT` stay on `GENES`, which the sections that need every dataset use. `GENE.TABLE` also keeps the fit status (NB and weighted) and `ANALYSIS.STATUS` records for every gene, quantity and mode whether it was eligible, run, estimated, given a bootstrap interval, tested and significant (`ANALYSIS.COUNTS` tallies them).
- Select Seurat columns by name, never by position (Seurat v5 changes `FindMarkers` output order).
- Validate numeric inputs at function entry (for example `BSIZE` in `SPLIT.FITS`).
- Do not commit data, `.rda` checkpoints, or cluster output. Keep them in `.gitignore`.

## Code annotation style
- Annotate each function and each analysis block with comments that explain the concept behind the step, such as why bootstrap draws must be independent.
- Write comments positively. State what the code does and why it works, not what used to break.
- Keep comments short and accurate. Update them whenever the code changes.

## Verification before finishing a task
- Run `Rscript -e "parse('R/functions.R'); parse('analysis/analysis.R')"` to confirm both files parse.
- Source `R/functions.R` and run any unit checks that exist for the functions you touched.
- Do not claim a result is unchanged unless a check confirms it. Expected result changes after the R and Seurat upgrade include `FindMarkers` fold changes, newer GO and KEGG annotations, and Monte Carlo seed behavior.
